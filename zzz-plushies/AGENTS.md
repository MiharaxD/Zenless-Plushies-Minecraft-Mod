# Guia para trabalhar neste projeto

1. Leia primeiro [docs/INDEX.md](docs/INDEX.md). Abra somente os documentos e arquivos de código ligados à tarefa atual.
2. Confirme fatos que podem ter mudado no código antes de editar; os documentos são um mapa, não substituem o código.
3. Mantenha a mudança restrita ao pedido. Preserve os JARs e snapshots em `versions/` e os lançamentos antigos em `output/`.
4. Depois de alterar comportamento, atualize somente a seção pertinente da documentação técnica. Registre o que foi e o que não foi testado.
5. Não faça capturas de tela rotineiras durante testes. O usuário acompanha o processo e pediu para economizar contexto.

Converse em português brasileiro, de forma casual e direta, seguindo as preferências do usuário nesta conversa.
